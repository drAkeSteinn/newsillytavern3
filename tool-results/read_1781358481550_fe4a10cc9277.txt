    23→## FASE 1: Sistema de Estados Emocionales Autónomo
    24→
    25→### Arquitectura
    26→
    27→**Enfoque Híbrido** = Atributos Emocionales + Evaluación Post-Respuesta + Tool Calling
    28→
    29→### Componentes a implementar:
    30→
    31→1. **Tipos nuevos** (`src/types/index.ts`):
    32→   - `EmotionalStateConfig` - Configuración del sistema emocional por personaje
    33→   - `EmotionalEvaluation` - Resultado de evaluación emocional
    34→   - Extender `CharacterCard` con `emotionalConfig?: EmotionalStateConfig`
    35→   - Extender `CharacterSessionStats` con `emotionalState?: string`
    36→
    37→2. **Evaluador Emocional** (`src/lib/emotions/emotion-evaluator.ts`):
    38→   - Función `evaluateEmotionalState()` que hace consulta ligera al LLM
    39→   - Usa los últimos N mensajes como contexto
    40→   - Retorna el estado emocional como string
    41→   - Sistema de caché para evitar re-evaluaciones innecesarias
    42→   - Rate limiting configurable (no evaluar cada turno si no se desea)
    43→
    44→3. **Integración en Stream API** (`src/app/api/chat/stream/route.ts`):
    45→   - Después de cada respuesta del LLM, ejecutar evaluación emocional
    46→   - Actualizar `sessionStats.characterStats[charId].emotionalState`
    47→   - Emitir evento SSE `emotional_update` para que el frontend actualice sprites
    48→
    49→4. **Integración en Prompt Builder** (`src/lib/llm/prompt-builder.ts`):
    50→   - Nueva key `{{emocion}}` que resuelve al estado emocional actual
    51→   - Se inyecta en la sección de personalidad/atributos del personaje
    52→   - Formato: "Estado emocional actual: {emocion}"
    53→
    54→5. **Integración con Sprites** (`src/lib/sprites/condition-evaluator.ts`):
    55→   - Las condiciones de sprites ya soportan `StatRequirement`
    56→   - Solo falta que `{{emocion}}` se resuelva como un stat más
    57→   - Automáticamente: si emoción cambia → se reevalúan condiciones → sprite cambia
    58→
    59→6. **UI: Configuración Emocional** (en character-editor.tsx):
    60→   - Sección "Estados Emocionales" en la pestaña de Stats/Atributos
    61→   - Definir estados posibles (lista de keywords)
    62→   - Estado inicial
    63→   - Activar/desactivar evaluación automática
    64→   - Intervalo de evaluación (cada 1, 2, 3 turnos)
    65→
    66→7. **Indicador Visual** (en chat):
    67→   - Badge/indicador del estado emocional actual del personaje
    68→   - Se actualiza en tiempo real vía SSE
    69→
    70→### Flujo de datos:
    71→```
    72→LLM Response → Emotion Evaluator (lightweight LLM call) → Update sessionStats
    73→  → SSE event `emotional_update` → Frontend updates:
    74→      1. Emotion badge in chat
    75→      2. Sprite conditions re-evaluated → sprite changes
    76→      3. Next LLM call includes {{emocion}} in prompt
    77→```

    81→## FASE 2: Memoria de Relaciones Evolutiva
    82→
    83→### Arquitectura
    84→
    85→**Enfoque** = Tool Calling + Key en Prompt + Evaluación Periódica
    86→
    87→### Componentes a implementar:
    88→
    89→1. **Tipos nuevos** (`src/types/index.ts`):
    90→   - `RelationshipEntry` - Relación entre personaje y otro entidad
    91→   - `RelationshipMemoryV2` - Extensión del RelationshipMemory actual
    92→   - Extender `CharacterMemory` con `relationshipsV2: RelationshipEntry[]`
    93→
    94→2. **Nuevo Tool: `update_relationship`** (`src/lib/tools/`):
    95→   - Parámetros: `targetName`, `trustDelta`, `sentimentDelta`, `notes`
    96→   - El LLM lo llama cuando la interacción cambia significativamente
    97→   - Actualiza el store de relaciones
    98→   - Retorna confirmación
    99→
   100→3. **Key `{{relaciones}}`** en prompt-builder y key-resolver:
   101→   - Inyecta bloque formateado de relaciones en el prompt
   102→   - Formato:
   103→     ```
   104→     [RELACIONES DEL PERSONAJE]
   105→     - Con {{user}}: Confianza 7/10, Sentimiento: cariño. Nota: Se conocen desde la infancia.
   106→     - Con PersonajeB: Confianza 3/10, Sentimiento: desconfianza. Nota: Tuvo un conflicto.
   107→     ```
   108→
   109→4. **Evaluación Periódica de Relaciones** (opcional, cada N turnos):
   110→   - Similar al emotion evaluator pero para relaciones
   111→   - Consulta ligera: "¿Han cambiado las relaciones del personaje?"
   112→   - Solo actualiza si hay cambio significativo
   113→
   114→5. **UI: Visor de Relaciones** (en character panel o sidebar):
   115→   - Lista de relaciones con barras de confianza/sentimiento
   116→   - Historial de cambios
   117→
   118→### Respuesta a la pregunta del usuario:
   119→- **¿Es como un call tool?** SÍ, principalmente. El LLM usa `update_relationship` para actualizar relaciones.
   120→- **¿En qué parte del prompt se agrega?** Se inyecta como `{{relaciones}}` en la sección de atributos/stats del personaje, DESPUÉS de la personalidad y ANTES del escenario.

   124→## FASE 3: Proactividad Inteligente
   125→
   126→### Mejoras a implementar:
   127→
   128→1. **Contexto de Conversación para Nudge**:
   129→   - El nudge proactivo incluye los últimos 3-5 mensajes como contexto
   130→   - Evita que el personaje diga algo incongruente
   131→
   132→2. **Variación de Nudges**:
   133→   - Pool de templates de nudge que rotan
   134→   - Templates por estado emocional (si está triste → nudge empático)
   135→   - Templates por tiempo sin actividad (corto → casual, largo → preocupado)
   136→
   137→3. **Detección de Temas Abandonados**:
   138→   - Si se habló de un tema y se abandonó, el personaje puede retomarlo
   139→   - Usa embeddings para detectar temas
   140→
   141→4. **Cooldown Temático**:
   142→   - Si el personaje habló de X, no vuelve a hablar de X por N minutos
   143→   - Evita repetición
   144→
   145→5. **Proactividad en Group Chats**:
   146→   - Actualmente deshabilitada para grupos → habilitar con estrategia específica
   147→   - Personaje reacciona cuando otro personaje dice algo relevante
